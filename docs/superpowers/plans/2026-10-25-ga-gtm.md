# GP-376 GTM + GA4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** gitprice.com loads GTM `GTM-PLZZJV54` → GA4 `G-SM4YKS90F0` under Consent Mode v2 (cookieless until Allow), emits the spec's event set to GA and Heap, and ships the container JSON, setup docs and updated EN/AR legal copy.

**Architecture:**
- **Consent and loading.** An inline consent-default script plus the GTM snippet are rendered by `Analytics.tsx` (production + `NEXT_PUBLIC_GTM_ID` only). `lib/consent.ts` pushes `gtag('consent','update')` and clears `_ga*` cookies on Decline.
- **Events.** One `track()` helper writes to `dataLayer` and to `heap.track`. Clicks are declarative via `data-gp-track` attributes and one delegated listener. Sections use one IntersectionObserver. Tally submissions arrive via `postMessage` in `TallyEmbed`.
- **GTM config.** GTM tags, triggers and variables live in `docs/analytics/gtm-container.json`, validated by a unit test.

**Tech Stack:** Next.js 15.5 app router, React 19, TypeScript, vitest (`tests/`), Playwright (`e2e/`). Monorepo `design-system/i18n` with `node --test` metrics.

**Spec:** `docs/superpowers/specs/2026-10-25-ga-gtm-design.md`. It is approved, including the legal copy verbatim.

## Review Focus

1. **GTM blocked by an ad blocker.** `track()`, the consent update and the listeners all run with `window.dataLayer` present but GTM never loading. Nothing throws and the page works (Task 3 test: `track` with no gtm and no heap).
2. **Returning visitor who already allowed.** With the `gp_consent=allow` cookie set before load, the inline script issues the `granted` update before GTM loads (Task 2 test: the inline script string with the cookie set).
3. **Decline after Allow on the apex.** `_ga` cookies set on `.gitprice.com` are expired on every parent domain, not only the host (Task 2 test: hostname `www.gitprice.com`, cookies `_ga`, `_ga_SM4YKS90F0`, `_gid`).
4. **Foreign `postMessage`.**
   - A `Tally.FormSubmitted` from another origin is ignored.
   - So is one from the other `TallyEmbed`'s iframe on the same page (hero vs bottom).
   - Neither fires `waitlist_submit` with the wrong placement (Task 4 tests).
5. **Duplicates.** `section_view` must not fire twice for the same section in one page view (re-render, observer re-entry), and must fire again after client navigation to a new page (Task 3 test).
